# LastLight 0.1.8

LastLight 0.1.8 focuses on repeated-query efficiency. It keeps the large-document retrieval behavior introduced in 0.1.7 while removing avoidable tokenization and passage-extraction work from the hot path.

## Highlights

- Adds a query-independent lexical corpus representation containing body token counts, unique token sets, title/tag tokens, body lengths, and normalized searchable text.
- Caches that lexical corpus across equivalent searches using the same deterministic corpus-signature model as the existing retrieval-unit and BM25 caches.
- Tokenizes and expands each lexical query once per corpus search instead of once per ranking unit.
- Preserves the established `lexical_score()` helper and verifies exact score parity between single-document scoring and prepared batch scoring.
- Invalidates lexical prepared state automatically when ranked content or metadata changes.
- Defers passage extraction until after the best unit per source is known and the final `top_k` cut has been applied.
- Avoids sentence-window construction for losing chunks and lower-ranked sources that cannot appear in the returned results.
- Shares the same final result materialization path between lexical and BM25 while preserving scores, confidence, matched terms, tie behavior, and public source identity.
- Adds regressions proving passage selection runs only for final winners, including chunk-heavy long documents.

## Repeated-query efficiency

For an unchanged corpus, LastLight now reuses three layers of deterministic preparation:

1. hierarchical retrieval units for sufficiently large documents;
2. lexical token statistics or BM25 corpus statistics for those ranking units;
3. final passage extraction only for the results that survive source collapsing and `top_k`.

This is especially useful for interactive offline sessions where many questions are asked against the same local knowledge pack. The changes reduce repeated pure-Python text processing without introducing a database, background service, native extension, or runtime dependency.

## Compatibility

The public `LastLight` API, retrieval scores, confidence thresholds, result types, refusal behavior, and Knowledge Pack Format v1 are unchanged. Existing packs do not need to be rebuilt. Python 3.10, 3.11, and 3.12 remain supported, and the runtime still has no dependencies outside the Python standard library.

## Upgrade

```bash
python -m pip install --upgrade lastlight
```
