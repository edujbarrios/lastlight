# LastLight 0.2.1

LastLight 0.2.1 is a maintenance release focusing on trustworthy offline
answer decisions and hardened local audit metadata. The retrieval algorithms,
knowledge pack format and built-in emergency guidance are unchanged.

## Fixes

- **Consistent calibrated refusals in the CLI** (#98): JSON, source summaries,
  JSONL batch output, field guides and `--fail-on-refusal` now use the same
  deterministic acceptance decision as the Python API and human-readable
  `LastLight.answer()`. A weakly covered, ambiguous medium-confidence match
  no longer slips through those older output pathways.
- **Reliable index integrity checks** (#99): rejects malformed or incomplete
  index entries, invalid SHA-256 digests, duplicate paths, invalid version
  types and contradictory document counts before declaring an audit index valid.
- **Finite adaptive energy budgets** (#100): CLI rejects `NaN` and infinite
  values at argument parsing rather than feeding them to the retrieval policy.

## CI and publishing

- Add a guarded release-PR workflow (#101) that builds, validates and uploads
  releases to PyPI using Trusted Publishing when an intentional
  `[publish-pypi]` commit reaches `main`.
- Retain manual GitHub Release publication support, protected `pypi`
  environment and isolated wheel checks.
- Keep the offline core evaluation and unit/integration checks on Python
  3.10, 3.11 and 3.12.

## Compatibility

- Python 3.10+; standard library runtime, without network or LLM dependencies.
- No changes to Pack Format v1, public Python method signatures, or retrieval
  scoring. Answer acceptance may be more conservative for ambiguous queries
  in CLI outputs, to match the previously shipped calibrated decision policy.
- This release does **not** independently verify scientific or emergency
  advice in third-party knowledge packs.

## Install

```bash
python -m pip install --upgrade lastlight==0.2.1
```
