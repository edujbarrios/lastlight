# LastLight 0.1.4

LastLight 0.1.4 is a focused reliability and public-contract hardening release.

## Highlights

- Preserves mounted pack name, version, source, and path on search results when a single explicit knowledge pack is used.
- Validates public `top_k` values consistently across `search()`, `query()`, `answer()`, and `plan()` instead of silently coercing invalid limits.
- Fails fast with `PackError` when the public `LastLight` facade receives a missing, empty, or unsupported explicit knowledge source.
- Prevents adaptive query-risk terms from matching inside unrelated words.
- Rejects invalid chunking limits instead of allowing non-terminating chunk generation.
- Handles valid JSON indexes with malformed top-level shapes without crashing.
- Keeps directory pack manifests inside the pack root, including symlink escape protection, and applies the same manifest size limit used for ZIP packs.
- Aligns directory and ZIP Markdown discovery for case-insensitive `.md` extensions and hidden metadata paths.
- Clears stale session context when the user starts a new topic, so a refused standalone query cannot leak the previous topic into a later short follow-up.
- Matches safety triage rules on token and phrase boundaries instead of raw substrings, avoiding false triggers such as `gas` inside `Vegas`.
- Isolates adaptive retrieval decision metadata per execution context so concurrent users of one engine do not observe another request's plan.

The low-level repository and application-factory primitives remain available for internal tooling, while stricter validation is enforced at the stable public library boundary.

The runtime remains stdlib-only, the Pack Format v1 schema is unchanged, and no network connection is required once the Python package and knowledge packs are local.

After publication:

```bash
python -m pip install --upgrade lastlight
```
