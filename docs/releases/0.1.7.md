# LastLight 0.1.7

LastLight 0.1.7 extends the large-document work from 0.1.6 so retrieval remains focused even when a manual has oversized sections or little/no Markdown structure, while also reducing repeated preparation cost across queries.

## Highlights

- Adds bounded, paragraph-aware ranking chunks for large documents, with each internal unit capped at 1,800 characters.
- Carries up to 250 characters of complete trailing context into the next unit so relevant evidence near chunk boundaries is less likely to be separated.
- Applies hierarchical retrieval to documents of at least 4,000 characters even when they have no headings.
- Handles manuals with a single oversized Markdown section instead of requiring multiple non-empty sections before large-document retrieval activates.
- Preserves ATX heading hierarchy as ranking-title context before splitting oversized sections into bounded units.
- Keeps the original `KnowledgeDocument` as the public source; internal chunks never become synthetic public paths or pack entries.
- Collapses multiple matching units back to the best result per source document, preserving `top_k` behavior across large manuals.
- Caches deterministic retrieval units for repeated lexical and BM25 queries against equivalent corpora.
- Invalidates prepared-unit caches when document content or ranking metadata changes, while retaining the existing BM25 statistics cache.
- Adds regressions for relevant guidance near the end of long unstructured documents, bounded unit generation, chunk overlap, and cache reuse/invalidation.

## Large-document behavior

Documents below 4,000 characters keep the established document-level ranking path. Larger documents use a hierarchical internal representation:

1. Markdown headings define local retrieval regions when available.
2. Each region is packed into bounded paragraph-aware units.
3. Neighboring units retain a small amount of complete trailing context.
4. Lexical or BM25 ranking scores those units.
5. The best unit per original source document is retained.
6. Passage selection runs only inside the winning unit.

A large unstructured field log therefore gets the same bounded ranking treatment as a structured manual, while a structured guide still benefits from heading-path context.

## Repeated-query efficiency

The chunked representation is deterministic for a given ordered corpus. Both fixed retrieval strategies now cache those prepared units by corpus signature, so repeated queries do not repeatedly parse headings and reconstruct the same chunks. BM25 continues to cache its query-independent ranking statistics on top of the prepared units.

Changes to path, source hash, title, tags, priority, or body invalidate prepared state automatically.

## Compatibility

The public `LastLight` API, result types, refusal behavior, and Knowledge Pack Format v1 are unchanged. Existing packs do not need to be rebuilt. Python 3.10, 3.11, and 3.12 remain supported, and the runtime still has no dependencies outside the Python standard library.

## Upgrade

```bash
python -m pip install --upgrade lastlight
```
